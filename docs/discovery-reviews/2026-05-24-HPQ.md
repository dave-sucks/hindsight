## What the discovery run SHOULD do, step by step

### Step 1 — Read the discovery surfaces (feed-gated)

Per the post-#326 prompt, the agent's first assistant turn should emit **only the surfaces matching Tech Momentum's `feeds`**:

| Tool | Should call? | Why |
|---|---|---|
| `read_signals` | **YES** (always) | Universal push channel; the router has already feed-fenced the stream. |
| `get_market_movers` (`scope:"universe"`) | **YES** | Tech Momentum's `feeds` includes `MARKET_MOVERS_GAINERS` and `MARKET_MOVERS_ACTIVES`. Pull tool fires. |
| `get_earnings_calendar` (`scope:"universe"`) | **NO** | Tech Momentum is NOT subscribed to `EARNINGS_CALENDAR`. The post-#326 prompt should explicitly tell the agent "DO NOT call get_earnings_calendar." |

This is the load-bearing test of the #326 feeds-gating change. Pre-#326, all three surfaces fired unconditionally → 20-30 noise candidates and the agent had to triage harder. Post-#326, the agent only sees the surfaces matching the analyst's stated edge.

### Step 1.5 — Triage narration (kept from pre-Phase-2)

After Step 1 returns, the agent should narrate 8-12 candidates with 1-2 sentence gut-takes. This step is preserved verbatim from the pre-Phase-2 prompt — it's the audit trail that lets future smaller/faster models read the parent's reasoning before deciding what to dispatch.

### Step 2 — Pass-1 cheap research on triaged survivors

For each candidate the agent flagged in triage, it should call:

1. **`get_theses` with `tickers: [<candidate>]`** — cross-analyst overlap check.
2. **`get_stock_data` with `ticker: <candidate>`** — live quote + 7d news + technicals.

Then score on the 4-dim composite:
- `trendStrength` (0-3)
- `relativeStrength` (0-3)
- `entryQuality` (0-2)
- `catalystFreshness` (0-2)

Pre-committed composite for HPQ: **6-7/10**.
- `trendStrength` = 3 — fresh 52w-high breakout, SMA20 > SMA50 stack rising.
- `relativeStrength` = 1 — strong on the day but weakest growth in peer group (4.4% YoY vs WDC 32%, HPE 14.5%).
- `entryQuality` = 1 — RSI 76.7, 19% above SMA20 — extended but not blow-off (RSI < 80).
- `catalystFreshness` = 2 — tariff pull-forward narrative + Q1 beat are both fresh and dated.

Composite **7/10** → above the dispatch floor (≥4) but below NVTS's 8/10.

### Step 3 — Per-candidate action

Per the post-#326 prompt with `DISPATCH_CAP = 2`:

- **Composite ≥ 4** → eligible for `dispatch_thesis_research(mode:"mint")`. Hard cap of 2.
- **Composite < 4 but researched** → `record_thesis(direction:'PASS', reasoning + ≥1 invalidation_condition)`.
- **Not researched** → skip, narrate dismissal.

Tech Momentum is likely to have **>2 composite-≥-4 survivors** in a fresh week (NVTS at 8, HPQ at 7, BB at 6, HLIT at 5, INTC at 4 all clear the floor). The prompt explicitly directs: *"If you have more than DISPATCH_CAP composite-≥-4 survivors, dispatch your DISPATCH_CAP highest-conviction picks and PASS-record the rest."* So we expect:

- 2 dispatches: NVTS + HPQ (the top-2 by composite + freshest catalysts)
- 3 PASS rows: BB, HLIT, INTC

### Step 4 — `record_run_summary` listing dispatched / passed / skipped

`primary_decision: "WATCH"` (since the cap was hit but no trade was placed). `ranked_picks` should cover all three buckets. `decision_rationale` should explicitly call out the cap interaction ("only 2 dispatch slots; bottom 3 became PASS").

### Step 5 — `complete_run`

Parent ends `status = "COMPLETE"`. Child `THESIS_WRITER` runs may still be in-flight at this point — that's expected.

## What the HPQ thesis-writer child should produce

Once `dispatch_thesis_research(ticker:"HPQ", mode:"mint", analyst_id:"<TM_id>", reason:"…")` fires, the child `THESIS_WRITER` run takes over. Expected child workflow (per `lib/agent/system-prompts/thesis-writer.ts` and `lib/agent/run-thesis-writer.ts`):

1. **`write_thesis_research`** — fans out to 7 structured-data fetches in parallel (financials, analyst coverage, insider activity, earnings history, peers, filings, stock data) and then synthesizes via Claude Sonnet 4.6 + web_search. Returns 9 structured sections + citations.
2. **`get_stock_data`** — live quote anchor for entry_price / target / stop sizing.
3. **`record_thesis`** — mints the WATCHING thesis. **Auto-clamped to WATCHING by `forceWatchingMint: true`** in the dispatch payload (PR #316).
4. (Optional) **`update_thesis`** — refresh in the same run if the writer decides to adjust after re-reading.
5. **`complete_run`**.

Pre-committed HPQ thesis shape (what the child should produce):

```ts
{
  ticker: "HPQ",
  direction: "LONG",     // forced by analyst's LONG bias + bullish setup
  status: "WATCHING",    // forced by forceWatchingMint clamp

  entry_price: ~$25.25,  // from get_stock_data; the live quote on dispatch day
  target_price: ~$29-30, // prior 52w high $29.55 is the natural breakout-completion target
  stop_loss:   ~$22-23,  // below day's open / SMA20 zone, sized for R/R ≥ 2:1
```

## Specific failures to watch for (Phase 2 edition)

Listed in pipeline order:

1. **Parent agent calls `get_earnings_calendar` despite no EARNINGS_CALENDAR subscription.** → Feeds-gating in PR #326 didn't take effect (prompt didn't render the DO-NOT-CALL block, or agent ignored it).
2. **Parent agent dispatches > 2 thesis-writer runs.** → `DISPATCH_CAP` instruction is being violated. Cap is soft (prompt-only); GPT-5.5 usually honors it but a violation here motivates Layer-1 enforcement.
3. **Parent agent mints a LONG/SHORT WATCHING thesis directly via `record_thesis`.** → Two-pass funnel broken; the agent is duplicating work the dispatched child should own.
4. **Dispatched child mints `status = "ACTIVE"` instead of `WATCHING`.** → `forceWatchingMint` clamp failed (was added in PR #316; should be in payload from #321's wiring).
5. **Child thesis has empty `bullCase` or `bearCase` JSONB.** → Section parser broke on the deep-research output, OR the model didn't produce that section. Both have happened in pre-#321 thesis-writer testing.
6. **Child thesis `bearCase` is fluff** ("market volatility", "macro risk") without naming the specific consensus skew or the tariff-pull-forward reversal risk. → bear-case substance bug from #321's known-issues list.
7. **Parent and child Theses both reference the same HPQ ticker simultaneously.** → Race condition; child should be the sole writer.
8. **Child thesis writes target < entry or stop > entry for LONG.** → Shape gate should reject; if it lands the gate is broken.
9. **`source_kind = "ROUTED_SIGNAL"` with empty `source_signal_ids`.** → Zod gate should reject; HPQ came from `get_market_movers`, so the correct provenance is `source_kind = "WEB_SEARCH"` with a `source_rationale` string.
10. **Parent's PASS rows missing `invalidationConds`.** → Belief-gate variant for PASS rows (≥1 required); if it lands the gate is broken.
11. **Parent run ends `status = "FAILED"`.** → Could be the prose-termination bug. Tool-call discipline block is supposed to prevent it.
12. **Child run never completes** (stays RUNNING > 10 min). → Inngest function timeout or model hang. Cap on `concurrency: { limit: 5 }` and child `maxDuration: 800` should bound it.

## Calibration: what would be GOOD ENOUGH for a Phase-2 mechanics pass

The bar for "Phase 2 funnel works mechanically, quality deferred":

✅ Parent run completes (not FAILED).
✅ Parent only called the Step-1 surfaces matching Tech Momentum's `feeds` (specifically: `get_earnings_calendar` NOT called).
✅ Parent dispatched ≤ 2 children.
✅ Parent produced PASS rows for researched-but-cap-exceeded candidates.
✅ Each dispatched child completed with a `Thesis` row, all 9 flat section columns non-null, ≥1 triggers attached, shape gate satisfied.
✅ Run summary lists dispatched / passed / skipped buckets.

Quality issues explicitly deferred:
- Whether the HPQ thesis-writer's chosen entry/target/stop levels are *actually* good (Tech Momentum's `analystPrompt` calibration is a separate workstream).
- Whether 7/10 composite is the "right" score for HPQ — the rubric is calibrated for momentum and applied universally (P1-9).
- Whether the bear case is substantive enough (a recurring quality concern flagged in PR #321's body).
