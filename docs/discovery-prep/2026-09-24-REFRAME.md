# Discovery, reframed — 2026-09-24

> **What this is:** the pre-read for the analyst-by-analyst discovery sessions that follow it.
> Three parts: what the discovery skill gets right and where it has gone stale; what the live
> book actually needs; and how discovery works now that the app can enumerate most of what
> used to be scouted by hand. Every number below was read from the database or a live tool
> call on Thursday 2026-09-24. Nothing is taken from older audits.
>
> **Scope: discovery only.** Nothing else.

## Part A — The skill, reviewed

`/discovery-prep` (`docs/prompts/DISCOVERY_PREP.md`) + `docs/DISCOVERY_PLAYBOOK.md` +
`docs/discovery/scout-roster.md` + `docs/discovery/FUNNEL.md`.

### What holds up — keep all of it

- **The Scout Loop.** Grok's unit is people, not stocks. Theme → who has been right → what
  they're on now → why is it still cheap. Multi-message by design, which matches how the
  operator actually uses Grok.
- **The query rules learned the hard way** (08-09): two filters at retrieval, everything else
  labelled and filtered in the paste; never require an in-post citation; never scope a
  summarize turn to a thin thread; fish where the fish are — X has a biotech beat and no
  docket beat.
- **Convergence is two metrics.** Calendar convergence verifies a date. Trader convergence is
  a crowding warning. The most-converged name in the August sweep was a $0.5B unread binary.
- **Calendar-first for dated events.** The candidate universe for the Catalyst seat *is* a
  calendar; Grok is the risk layer on top, not the source.
- **Every survivor terminates in a row** — WATCHING with a plan, or PASSED with a reason.
  "Still in the research queue" cost PWR and ROK in August.
- **Cap dispatches to free slots, not to a constant.** Five dispatches into a two-slot seat
  is how a 14-name bench became 19.
- **US-listed, liquid enough for the position, in the prompt itself** for any supply-chain
  theme — half the GLP-1 session was spent on Bachem and Divi's.

### What has gone stale

1. **Every per-analyst query block predates the tools built since 2026-09-10.** They route
   everything through Grok and Perplexity, including the parts the app now enumerates from
   primary sources. The PEAD "Step 2 Perplexity" prompt *is* `run_screen(PEAD)` now. The
   Catalyst "Perplexity calendar" prompt *is* `get_catalyst_calendar` now — and better, because
   it reads the company's own 8-K instead of a tracker that recycles last year's dates (the
   06-05 finding that killed Perplexity-led Catalyst discovery).
2. **The Hindsight paste blocks never tell the agent to verify with its own tools.** They say
   "triage against the mandate." The 09-22 session showed what that produces: five biotechs
   reviewed, zero filings opened, two web searches instead. Every paste needs the line:
   *confirm any date or claim against `get_catalyst_calendar` / `get_sec_filings` /
   `get_earnings_calendar` before scoring; if the paste and the primary source disagree, the
   primary source wins.* AIR's earnings date and PRAX's PDUFA date are both cases where a
   secondary source was wrong.
3. **The roster is thin where the money is.** Biotech bench: graded 08-09 as *date sources,
   not alpha sources* — none showed foresight. PEAD bench: **empty, never seeded.** Aging:
   empty (Play D transfer failed). Momentum: retired. So for two of three live seats there is
   no bench at all, and for the third the bench is only useful for "is the date real / how
   crowded."
4. **The improvement loop has never run.** `FUNNEL.md` has three rows, all Catalyst, all
   August. `docs/discovery/raw/` **does not exist** — no prompt has ever been filed beside the
   output it produced, so a thin session has never been distinguishable from an empty window.
   PEAD and Compounder have zero funnel history.
5. **The skill's input pointer is broken.** It says to read the latest
   `docs/analyst-quality/*.md` "Feed to Discovery" section. The last two reviews (08-30, 09-02)
   don't have one — they use (a)–(e) sections. The 08-30 review's "(c) Discovery" and "(d) The
   manual discovery pack" are the real input, and they are three weeks old: two of their three
   fence proposals have since been applied and the third (PEAD's sector fence deleted) too.
6. **No notion of discovery *types*.** The playbook has one shape — scout externally, paste
   in. It has nothing for "the app enumerates this itself, ask it directly," nothing for
   entry-timing on names already watched, and nothing for what a sold name teaches.

## Part C — Discovery, reframed around what the app can do now

### The contract: what "discovered" means

A name is not discovered when it is mentioned. It is discovered when it is a `WATCHING`
thesis with **a setup named, a buy level (or an explicit "no entry until X"), a floor, and —
for a dated event — a `catalystDate`.** That is the shape the triggers read:

- `catalystDate` → the "N days before the event" review fires (proven live on MIRM 09-18).
- Any watched name → the account's earnings rules fire the heads-up and the beat/miss
  (proven live on AIR and LUXE 09-18) and the filing rule fires on a material 8-K (BMRN).
- A buy level → `ENTER` fires on the crossing → tactical run → proposal (MIRM 09-17).

So every session ends with rows in that shape, or PASS rows with the reason. Nothing else
counts.

### The six types, by where the candidate comes from

| # | Type | Source | Seats | Cadence | Tool / step |
|---|---|---|---|---|---|
| 1 | **Screen** — the app computes candidates from a setup's numbers | in-app | PEAD (universe); all three (`scope:"book"` for entry timing) | Wed + Fri; weekly for book | `run_screen` |
| 2 | **Calendar** — what's scheduled that we don't own | in-app | PEAD (`get_earnings_calendar`), Catalyst (`get_catalyst_calendar`) | Sun/Mon | one call each |
| 3 | **Filings** — an event already happened and was filed | in-app | Catalyst (8-K 8.01/1.01 tape, 13D), all (RED tier as an avoid-list) | 2×/week | `get_sec_filings` |
| 4 | **Movers** — the price moved, ask why | in-app | Catalyst (biotech gaps as an event detector) | daily, 1 min | `get_market_movers` |
| 5 | **Scout** — an unbounded universe or a qualitative read | Grok / Perplexity, multi-message | Compounder themes; Catalyst risk layer | Compounder monthly; Catalyst 2×/week | Scout Loop → paste |
| 6 | **Handed-in** — a list you saw somewhere | paste | any | ad hoc | the paste is the pool |

**Rules that apply to all six:**

- **In-app first.** Types 1–4 are free, primary-sourced, and take a sentence. Type 5 is for
  what the app cannot enumerate — a theme's universe, a scout's read on residual risk or
  crowding — never for a list the app already has.
- **Every scouted claim is verified in-app before scoring.** The paste says so explicitly.
- **Dispatch cap = free slots.** Overflow becomes a watch with a wake, not a fifth dispatch.
- **Every survivor terminates in a row.**
- **File the raw output** beside the prompt in `docs/discovery/raw/` and add the funnel row.
  This has never been done; start now.

### What the tools are, precisely, and their edges

| Tool | Gives | Edge to know |
|---|---|---|
| `run_screen` (PEAD, EPISODIC_PIVOT, MA_PULLBACK, BASE_BREAKOUT, MOMENTUM_FLAG) | 5–15 names with the numbers; every rejection named | **Universe pool is broken for the three chart setups** — it reads today's movers, which contradicts their own rules (DAV-300). Use `scope:"book"` for those. PEAD's pool is coherent. First failure wins; cap 40. |
| `get_earnings_calendar` (upcoming / reported × universe / coverage / all) | who reports, who beat, with figures | Vendor dates can be wrong (AIR was Sep 21 vs the company's Sep 29 — fixed in the trigger, not the tool). |
| `get_catalyst_calendar` | PDUFA dates from the companies' own 8-Ks, with the sentence and link; defaults to 70 days; `days` or `from`/`to` | **PDUFA only** for now. 44s cold for the whole market, sub-second after. Prompts don't mention it — only its description does. A moved date appears as two rows (PRAX 12-27 and 01-29) until the agent reads which is live. |
| `get_sec_filings` (company / coverage / universe / all × forms / items / tier × days) | any filing lane: 8.01/1.01 tape, DEFM14A, SCHEDULE 13D, RED tier | EDGAR can't filter by item natively — text search plus re-check. Exhibit links preferred. |
| `get_market_movers` | gainers / losers / actives with 5D / 1M / 6M | Only what moved *today*. **No prompt tells the agent what a mover means** (DAV-302's sibling). Today: SRZN +108% is a biotech event; SVRN +931%/6M is a shell. |
| `read_trade_results` | win rate, avg R, days held, give-back, by setup and by analyst; recent closes | The "past sales" lens. SRRK was sold 09-14, sixteen days before its own PDUFA. |
| `twitter_search` | Grok Live Search over X, handle-attributed, archetype-tagged | Budget-limited; sharp probes only. In-app Grok exists — for verification, not sweeps. |
| `get_insider_activity` | Form 4 buys/sells, 90 days | **Not on the chat allowlist** — research runs only. |
| `dispatch_thesis_research(mode:"mint", setup_id, screen_row)` | the writer mints the WATCHING row with a plan | `screen_row` ≤ 400 chars (fixed to trim, #678). |

### How the seats' own prompts stand

- Catalyst's prompt names PDUFA, 8-K and filings. PEAD's names 8-K. **Compounder's names no
  data tool at all.**
- The chat prompt (`modes.ts`) routes phrasings to tools for movers, earnings, screens and
  13Ds. **No line for the catalyst calendar** and no line telling a review of an event name
  to open the filing (DAV-302). The tool descriptions carry the judgment for now.
