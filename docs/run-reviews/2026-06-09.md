### [F] Production validation — #393 (ARQT silent-drop) holds end-to-end

The headline. On 06-05 the Catalyst tactical validated ARQT's ENTER trigger,
called `place_trade`, and the tool threw `Analyst <id> not found or not yours` on
a model-supplied stray `analyst_id` — silently dropping a HIGH-conviction live
entry ([P1-20 / #393](https://github.com/dave-sucks/hindsight/pull/393)). Today the
identical trigger re-fired (ARQT reclaimed $21.95 intraday after sitting at
$21.23–$21.54 through 06-08/early-06-09), `place_trade` created the proposal
cleanly, and it filled on approval. **The silent-drop class is closed and proven
on the live path.** The trigger machinery itself was never the issue — it fired
correctly both times; only the downstream tool was broken, and it's fixed.

### [Observation] Transient thesis-ACTIVE during PENDING_APPROVAL window

`place_trade` flips the paired thesis WATCHING→ACTIVE at **proposal-creation**
time, not at approval. SNOW therefore sat `thesis=ACTIVE` while
`position=PENDING_APPROVAL` for ~24h (6/08 10:04 → 6/09 09:48). It resolved
cleanly on approval, and `get_portfolio_context` filters PENDING_APPROVAL out, so
the next morning run (6/09) saw SNOW as a held ACTIVE name with no contradicting
portfolio row. No harm today — but a buy that sits pending across a daily-run
boundary presents the agent an ACTIVE thesis whose position isn't yet real. Worth
confirming the daily run can't double-propose or misread it (Open Question 2).
