## New GAPS surfaced

Four new bugs filed in [`docs/GAPS.md`](../GAPS.md) — see that file for the
canonical text. Summaries here for review-self-containment:

### Bug #1 — `complete_run` preflight scope excludes PROMOTED (P0)

`lib/agent/tools/complete-run.ts:430,437`:
```ts
status: { in: ["ACTIVE", "WATCHING"] },
```

The unaddressed-theses gate's WHERE clause excludes PROMOTED. The gate
**physically cannot fire** on unresolved PROMOTED rows. This is the Layer-1
durable defense the system prompt's "every Live Theses row produces one
tool call" instruction relies on. Without it, Layer 3 is purely advisory.

**Fix:** add `'PROMOTED'` to the status array in both the
INTRADAY_TACTICAL/THESIS_WRITER scope (line 430) and the daily-run scope
(line 437). Verify `computeNeedsAction` returns a non-null value on
PROMOTED before this Layer 1 fix takes effect (otherwise the gate will be
in scope but compute "no action needed" — see Bug #2).

### Bug #2 — `computeNeedsAction` has no PROMOTED case (P0)

`lib/agent/needs-action.ts` defines three kinds: TRIGGER_FIRED,
TRIGGER_MATCHING_NOW, REVIEW_DUE. None of them surface "this row is
PROMOTED and requires resolution this run." For a PROMOTED thesis with
nextReviewAt days out and no fired triggers, `needsAction = null` → the
agent's prompt-internalized rule "needsAction == null → skip" makes it a
no-op.

**Fix:** add a 4th `NeedsAction` kind `PROMOTED_RESOLUTION_REQUIRED` with
precedence above REVIEW_DUE (but below TRIGGER_FIRED so a fired trigger
still wins). Surface paper-context fields in the payload so the agent's
prompt rendering has the conviction picture inline.

### Bug #3 — `Thesis.promotedAt` timezone-corrupted on write (P1)

Stored as `2026-05-26 16:42:31` (timestamp without time zone) for an event
at `04:42:31 UTC`. Same row, same Prisma model — `AgentConfig.updatedAt`
written at the same moment stored correctly as `04:42:31 UTC`. Likely a
`new Date().toLocaleString()` or similar wall-clock-to-UTC mishandle in
`lib/actions/promote-analyst.actions.ts` or its callers. Breaks the
natural-comparison check `researchUpdatedAt >= promotedAt` (returns FALSE
on every PROMOTED row).

**Fix:** trace the write site (likely a manual `Date` construction in the
promotion action), ensure it goes through Prisma's normal Date binding or
`new Date()` directly. Backfill the 3 existing rows with the correct UTC
timestamp.

### Bug #4 — Promotion fan-out THESIS_WRITER oversteps PROMOTED → WATCHING (P0)

Same bug family as PR #343's "ACTIVE refresh produces WATCHING template"
but for PROMOTED. The promotion fan-out's refresh ran with the
status-decision authority disabled (per system-prompt contract: "status
decision belongs to the daily-run agent on first live run") but the
thesis-writer still wrote `STATUS_CHANGED PROMOTED → WATCHING` for all 3
rows. Principal had to manually fix at 01:02 ET.

**Fix:** the thesis-writer's Layer-1 guard (`enter-guard.ts` per #343)
needs to reject status changes on PROMOTED rows the same way it rejects
HELD-actions on WATCHING and ENTER-on-ACTIVE. The Layer-3 prompt branch in
`run-thesis-writer.ts` needs a third state-conditional block:
"*** YOU ARE REFRESHING A PROMOTED THESIS — DO NOT CHANGE STATUS ***".
