## New Findings

### F1. INTRADAY_TACTICAL complete_run preflight requires `record_run_summary` (low-severity, wasted steps)

All 3 ENTER tactical runs got refused by the preflight 3-4× each, with the
literal refusal:

> complete_run refused: you must call record_run_summary BEFORE complete_run.
> Summarize this run's decisions (primary_decision, decision_rationale,
> ranked_picks) and call complete_run again.

Zero of the 9 tactical runs called `record_run_summary` today. So how did they
complete? Either (a) the preflight has a tactical bypass after N refusals, (b)
the tactical agent eventually narrated something the gate accepted as a
summary, or (c) the agent gave up calling complete_run and the run was marked
COMPLETE by some other path (timeout fallback?).

The `record_run_summary` requirement is sensible for MORNING_PLAN (it's the
ranked-picks artifact for the daily review) but doesn't obviously make sense
for a single-thesis tactical run. Either:

- **(prompt-side)** Teach tactical-mode agents in their system prompt that
  `record_run_summary` is the closer for any run, including tactical, and
  give them the expected shape for a 1-thesis tactical summary.
- **(tool-side)** Loosen the preflight for INTRADAY_TACTICAL mode — skip the
  `no_run_summary` check, only enforce `unaddressed_theses` against the
  single triggered thesis. This is cleaner per the three-layer principle:
  Layer 1 (tool) should know its own contract; tactical and daily-run runs
  ARE different shapes.

Open Question 2 picks this back up.

### F2. PR #266's preflight is provably working — yesterday's Open Question #3 answered

Yesterday's review flagged that `complete_run` counted 2-3 per OK run and we
didn't know why. Today's evidence resolves it cleanly: the preflight refuses
the first complete_run when the agent has unaddressed needsAction theses,
sends back an `unaddressed_theses` message listing them, and the agent goes
back and addresses each before calling complete_run again.

Sample refusal (Earnings Drift's first complete_run today):

```
complete_run refused: 4 active/watching thesises are flagged needsAction
but no update_thesis was called for them in this run. Resolve each by
calling update_thesis (with action result, change_status="INVALIDATED"
if no longer applicable...)
```

The agent then called update_thesis for each (including TSM), then
complete_run again, then succeeded.

**This is exactly the failure mode that killed yesterday's runs three days
ago** (the GOOGL "I'll prioritize it next session" narration → walk away →
record_run_summary keyword-list-fail). With PR #266's preflight in front,
the agent gets a structured refusal and recovers instead of giving up.
**The V2 design works as documented.**

### F3. TSM zombie healed without further intervention

Yesterday's F2 (Earnings Drift INVALIDATED TSM's thesis while the position
was still OPEN) was patched manually 2026-05-14 16:50 ET with a STATUS_CHANGED
ThesisUpdate row marked *"Manual revival: INVALIDATED → ACTIVE (zombie repair)"*.

The trigger evaluator picked up the resurrected ACTIVE thesis (overdue review
by 1 day) at 17:00 ET yesterday — fired `TRIGGER_FIRED: Scheduled review
overdue by 1d on TSM (ACTIVE)`. Today's Earnings Drift morning run handled
it cleanly: read needsAction, saw TSM, called `update_thesis` (triggers +
rationale, status preserved). No INVALIDATE recurrence. Position remains OPEN.

The underlying fix shipped in **PR #269** as a `zombie-position guard` in
`lib/agent/tools/update-thesis.ts`. So today's clean handling of TSM is the
combination of (a) the manual revival of the row, (b) the trigger evaluator
picking up the resurrected ACTIVE thesis, and (c) the agent now being unable
to re-create the zombie even if it tried. Three-layer defense in place.

### F4. Catalyst Event Raider's 12-second 5-tool run

Catalyst Event Raider produced only 5 tool calls in 12 seconds: read_signals,

- This analyst genuinely has nothing actionable in its book today and all its

  no unaddressed needsAction theses to flag.

Need to check: how many of this analyst's live theses have `nextReviewAt`

as intended. If non-zero, the analyst skipped real work. See Open Question 1.

-- Morning runs today
SELECT r.id, ac.name AS analyst, ac."useV2Prompt", r.status,

LEFT JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.mode = 'INTRADAY_TACTICAL'
  AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-15'

-- Per-tool totals across MORNING_PLAN runs today
WITH today_morning_runs AS (
  SELECT r.id FROM "ResearchRun" r
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-15'
),
toolcall_rows AS (
  SELECT (regexp_matches(rm.content, '"type":"tool-call","toolCallId":"[^"]+","toolName":"([^"]+)"', 'g'))[1] AS tool_name
  FROM today_morning_runs tr JOIN "RunMessage" rm ON rm."runId" = tr.id
)
SELECT tool_name, COUNT(*) AS n FROM toolcall_rows GROUP BY tool_name ORDER BY n DESC;

-- Per-analyst tool breakdown
WITH today_morning_runs AS (
  SELECT r.id, ac.name AS analyst FROM "ResearchRun" r
  JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-15'
),
toolcall_rows AS (
  SELECT tr.analyst, (regexp_matches(rm.content, '"type":"tool-call","toolCallId":"[^"]+","toolName":"([^"]+)"', 'g'))[1] AS tool_name
  FROM today_morning_runs tr JOIN "RunMessage" rm ON rm."runId" = tr.id
)
SELECT analyst, tool_name, COUNT(*) AS n FROM toolcall_rows
GROUP BY analyst, tool_name ORDER BY analyst, n DESC;

-- complete_run gate-bounce detector (find preflight refusals)
SELECT rm."runId", ac.name,
       CASE WHEN rm.content ILIKE '%no_run_summary%' THEN 'no_run_summary' END AS reason_a,
       CASE WHEN rm.content ILIKE '%unaddressed_theses%' THEN 'unaddressed_theses' END AS reason_b,
       CASE WHEN rm.content ILIKE '%run_already_failed%' THEN 'run_already_failed' END AS reason_c
FROM "RunMessage" rm
JOIN "ResearchRun" r ON r.id = rm."runId"
JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.mode IN ('MORNING_PLAN','INTRADAY_TACTICAL')
  AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-15'
  AND (rm.content ILIKE '%preflight%' OR rm.content ILIKE '%complete_run refused%');

SELECT ac.name AS analyst,

  SELECT t2.id FROM "Thesis" t2
  JOIN "ResearchRun" rr ON rr.id = t2."researchRunId"
