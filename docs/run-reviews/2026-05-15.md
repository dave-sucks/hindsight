## Pattern: the prose↔action contradiction is the day's dominant bug

5 PASS-archives across 3 analysts wrote rationales that contradicted the
structured `change_status: ARCHIVED` decision. The model is *hedging in
writing* while taking decisive structural action. The agent's *summary
output* (record_run_summary's ranked_picks) is correctly labeled
REMOVE_WATCH/PASS in every case. So:

- Structured state = correct
- Run-summary narrative = correct
- Per-thesis rationale text = contradicts both

This is the same shape of bug as the GOOGL `reasoningSummary` lie from
2026-05-13 (P0-10 in GAPS.md): free-text fields say one thing while
structured fields say another. The proposed fix in P0-10 was either to
deprecate state-bearing free text or to add a tool-side validator that
rejects rationales naming the wrong action. **Today's data argues the
validator approach is now necessary, not optional.** A rationale that says
"I'll maintain watch" while `change_status: ARCHIVED` should be rejected at
`update_thesis` — that's the simplest tool-side guard, and the agent will
self-correct on the retry.

### F1. INTRADAY_TACTICAL complete_run preflight requires `record_run_summary` (low-severity, wasted steps)

All 3 ENTER tactical runs got refused by the preflight 3-4× each, with the
literal refusal:

> complete_run refused: you must call record_run_summary BEFORE complete_run.
> Summarize this run's decisions (primary_decision, decision_rationale,
> ranked_picks) and call complete_run again.

Zero of the 9 tactical runs called `record_run_summary` today. So how did they
complete? Either (a) the preflight has a tactical bypass after N refusals, (b)
the tactical agent eventually narrated something the gate accepted as a
summary, or (c) the agent gave up calling complete_run and the run was marked
COMPLETE by some other path (timeout fallback?).

The `record_run_summary` requirement is sensible for MORNING_PLAN (it's the
ranked-picks artifact for the daily review) but doesn't obviously make sense
for a single-thesis tactical run. Either:

- **(prompt-side)** Teach tactical-mode agents in their system prompt that
  `record_run_summary` is the closer for any run, including tactical, and
  give them the expected shape for a 1-thesis tactical summary.
- **(tool-side)** Loosen the preflight for INTRADAY_TACTICAL mode — skip the
  `no_run_summary` check, only enforce `unaddressed_theses` against the
  single triggered thesis. This is cleaner per the three-layer principle:
  Layer 1 (tool) should know its own contract; tactical and daily-run runs
  ARE different shapes.

Open Question 2 picks this back up.
