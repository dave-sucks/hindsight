   marker before today.

**Why it matters today:** the daily-run prompt teaches conviction-modulated

**Fix path:** verify whether the migration is part of the prisma

### G — Resolver actionability is not stored, can't be audited from SQL alone
**Severity: process gap, doesn't affect today's data.**

`get_theses` returns `resolved.actionability` as a computed read-time
envelope ([lib/agent/resolved-thesis.ts](../../lib/agent/resolved-thesis.ts)). No persistence layer
captures the verdict that was returned to the agent at run start. The
review-time reconstruction in the table above is verbal (cross-reading
the agent's `update_thesis.rationale`), not authoritative. For Section
G adherence to be auditable, the resolver verdict needs to land in a
log row (or a `RunEvent` written when get_theses is called).

**Suggest:** add a one-line `RunEvent(type='resolver_snapshot')` per
`get_theses` call, recording `{thesisId, actionability, currentPrice,
triggerState}`. Diff is trivial and unlocks the Section G audit lane.
