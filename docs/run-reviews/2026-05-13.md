### Secular Theme + GOOGL — the most important finding

The agent's walk-through (from RunMessage text turns):

1. Turn 3: Listed today's signals (NVDA, MSFT). Listed "Portfolio" as
   **AVGO ($416.81) and GOOGL ($385.88, 4-day hold period)**. Listed
   "Theses Needing Action" as AMD and SMCI. **GOOGL was categorized as
   held-position context, not as an action item.**
2. Turn 4-5: Reviewed AMD, called `update_thesis`.
3. Turn 6-7: Reviewed SMCI, called `update_thesis`.
4. Turn 7 (end): "Now I'll summarize these actions and complete the run."
5. Turn 8: `record_run_summary` returned the promotion-gate failure
   message. Agent's response: *"The run encountered an issue due to an
   omission in the decision rationale: GOOGL met entry conditions but
   was not addressed in the summary."*
6. Turn 9 (final, before complete_run): *"The run is complete. I'll
   ensure that the GOOGL thesis is prioritized in the next session for
   appropriate action on the met entry conditions."*

**Root cause: position-thesis desync.** GOOGL had an OPEN position
(cmowxdgx8000404jpr2bnzyg0, $397.09 fill from 2026-05-08) but the
matching thesis (cmobfto9m00ew04l5r5j8uynv) was still `status = WATCHING`.
The thesis's `reasoningSummary` literally said *"Entry executed within max
position size limits"* — true at face value but contradicting the structured
`status` field. The agent read the prose and treated GOOGL as held.

This pre-existed PR #265's auto-promotion fix — for new trades placed after
PR #265, place_trade now flips WATCHING → ACTIVE inside the transaction. The
4 historical instances (AMD, AVGO, GOOGL, TSM) were patched manually in DB
end-of-day 2026-05-13.

**Two distinct failure modes stacked:**

**Failure mode A — agent never surfaced GOOGL as a triggered thesis.** The
desync made GOOGL look held to the agent's logic even though `needsAction`
should have been `TRIGGER_MATCHING_NOW` (price $385.88 > target $370). DB
patch + PR #265 auto-promotion closes this class going forward.

**Failure mode B — agent called complete_run after the gate marked run
FAILED.** Fixed end-of-day in PR #266: `complete_run` preflight now refuses
with `run_already_failed` and surfaces the failure reason in-conversation.

### EV Catalyst + TSLA — narration-gate false positive (not agent fault)

## Raw Queries

Same queries as 2026-05-12.md; substitute today's date.

```sql
-- Morning runs today
SELECT r.id, ac.name AS analyst, ac."useV2Prompt", r.status,
       (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS started_et,
       EXTRACT(EPOCH FROM (COALESCE(r."completedAt", NOW()) - r."startedAt"))::int AS elapsed_s,
       r.parameters->>'error' AS error_text
FROM "ResearchRun" r
LEFT JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.mode = 'MORNING_PLAN'
  AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
ORDER BY r."startedAt";

-- Per-tool totals across MORNING_PLAN runs today
WITH today_morning_runs AS (
  SELECT r.id FROM "ResearchRun" r
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
),
toolcall_rows AS (
  SELECT (regexp_matches(rm.content, '"type":"tool-call","toolCallId":"[^"]+","toolName":"([^"]+)"', 'g'))[1] AS tool_name
  FROM today_morning_runs tr JOIN "RunMessage" rm ON rm."runId" = tr.id
)
SELECT tool_name, COUNT(*) AS n FROM toolcall_rows GROUP BY tool_name ORDER BY n DESC;

-- Position-thesis desync detector (the GOOGL-class bug)
SELECT p.symbol, p.status AS pos_status, p."avgCost", p."openedAt",
       t.status AS thesis_status, t."entryPrice", t."targetPrice", t.id AS thesis_id
FROM "Position" p
LEFT JOIN "Thesis" t ON t.ticker = p.symbol AND t.status IN ('WATCHING','ACTIVE')
WHERE p.status = 'OPEN'
  AND (t.status = 'WATCHING' OR t.id IS NULL)
ORDER BY p."openedAt";
-- Expect: zero rows tomorrow. Any non-zero = a new desync slipped past PR #265.

-- Overdue-review backlog
SELECT
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')) AS active_or_watching,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < (NOW() - INTERVAL '7 days')) AS overdue_7d,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < NOW()) AS overdue_any
FROM "Thesis";

-- Trades + closes today
SELECT symbol, direction, status, quantity, "avgCost", "openedAt",
       "closedAt", "closeReason", "closeSource", "realizedPnl"
FROM "Position"
WHERE ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
   OR ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
ORDER BY COALESCE("closedAt", "openedAt");

-- RunEvent details (true failures vs quality-gate failures)
SELECT "runId", type, title, LEFT(message, 300) AS msg, "createdAt"
FROM "RunEvent"
WHERE "runId" IN (<today's morning run ids>)
ORDER BY "runId", "createdAt";

-- complete_run preflight failures (NEW — first surface tomorrow 5/14)
SELECT "runId", title, LEFT(message, 300) AS msg, "createdAt"
FROM "RunEvent"
WHERE type = 'run_failed'
  AND ("createdAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
  AND (message ILIKE '%preflight%' OR message ILIKE '%complete_run refused%')
ORDER BY "createdAt";
```
