## New Findings (not in yesterday's report)

### 🚨 Silent `place_trade` failure on Intraday Momentum Scalper
Two `place_trade` calls were made on INTC SHORT. Both produced **zero
Position rows**. `toolStats.byTool.place_trade = { count: 2, errors: 0 }`
— the error counter says no failures, but no position opened either.

Agent narration reveals what happened:
- **Attempt 1**: `SHORT INTC @ $120.61, target $116.19, stop $123.02`. Tool
  rejected — agent narrated "blocked because the current price exceeded the
  planned stop loss." Likely the place_trade live-price gate ([place-trade.ts](lib/agent/tools/place-trade.ts))
  caught it: live price had moved above $123.02 (the stop) by the time the
  trade hit Alpaca.
- **Attempt 2**: Agent re-priced to `SHORT INTC @ $125.72, target $121.01,
  stop $128.24`. Tool rejected — agent narrated "trade placement failed
  due to an issue with the analyst identifier." That's the second
  place_trade gate: `analyst_id` arg mismatch with `ctx.analystId`.

**Both legitimate rejections.** But `errors: 0` in toolStats is wrong —
they returned `ok: false` envelopes but the error counter didn't increment.
Worth investigating [morning-research.ts:218-235](lib/inngest/functions/morning-research.ts:218)
where the byTool error aggregation reads `r?.output?.ok === false`. Maybe
the result envelope shape varies for place_trade specifically.

This is a **diagnostic visibility bug, not a correctness bug** — the trades
correctly didn't happen, but our error telemetry says they did.

## Raw Queries

```sql
-- Morning runs today + tool call totals
SELECT r.id, ac.name AS analyst, ac."useV2Prompt", r.status,
       EXTRACT(EPOCH FROM (COALESCE(r."completedAt", NOW()) - r."startedAt"))::int AS elapsed_s,
       (r.parameters->'toolStats'->>'totalToolCalls')::int AS total_tool_calls,
       r.parameters->>'error' AS error_text
FROM "ResearchRun" r
LEFT JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.mode = 'MORNING_PLAN'
  AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
ORDER BY r."startedAt";

-- Per-tool totals across today's morning runs
WITH today_runs AS (
  SELECT r.id FROM "ResearchRun" r
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
),
toolcall_rows AS (
  SELECT (regexp_matches(rm.content, '"type":"tool-call","toolCallId":"[^"]+","toolName":"([^"]+)"', 'g'))[1] AS tool_name
  FROM today_runs tr JOIN "RunMessage" rm ON rm."runId" = tr.id
)
SELECT tool_name, COUNT(*) AS n FROM toolcall_rows GROUP BY tool_name ORDER BY n DESC;

-- Trades + closes today
SELECT symbol, direction, status, quantity, "avgCost",
       ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS opened_et,
       ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS closed_et,
       "closeReason", "closeSource", "realizedPnl"
FROM "Position"
WHERE ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
   OR ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13';

-- Overdue-review backlog
SELECT
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < (NOW() - INTERVAL '7 days')) AS overdue_7d,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < NOW()) AS overdue_any
FROM "Thesis";
```
