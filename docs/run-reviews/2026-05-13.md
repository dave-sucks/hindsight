## V2 Behavior (with PR #261 live)

### Secular Theme + GOOGL — the most important finding

The agent's actual walk-through (from RunMessage text turns):

1. Turn 3: Listed today's signals (NVDA, MSFT). Listed "Portfolio" as
   **AVGO ($416.81) and GOOGL ($385.88, 4-day hold period)** — and listed
   "Theses Needing Action" as AMD and SMCI. **GOOGL was categorized as
   held-position context, not as an action item.** GOOGL is a WATCHING
   thesis with no open position; the agent mislabeled.
2. Turn 4-5: Reviewed AMD, called `update_thesis`.
3. Turn 6-7: Reviewed SMCI, called `update_thesis`.
4. Turn 7 (end): "Now I'll summarize these actions and complete the run."
5. Turn 8: `record_run_summary` returned the promotion-gate failure
   message. Agent's response: *"The run encountered an issue due to an
   omission in the decision rationale: GOOGL met entry conditions but was
   not addressed in the summary."*
6. Turn 9 (final, before complete_run): *"The run is complete. I'll
   ensure that the GOOGL thesis is prioritized in the next session for
   appropriate action on the met entry conditions."*

The new V2 INVALIDATE teaching from PR #261 is **in the prompt** but it
**never got read against GOOGL** because the agent didn't see GOOGL in
the needsAction set. Two distinct failure modes stacked:

**Failure mode A — agent never surfaced GOOGL as a triggered thesis.**
Either:
- `get_theses.needsAction` returned null for GOOGL (a tool/computeNeedsAction bug — the
  trigger evaluator fired and the predicate is currently true, so
  `needsAction.kind = "TRIGGER_FIRED"` or `"TRIGGER_MATCHING_NOW"` should
  have been computed), OR
- `get_theses` returned a needsAction value but the prompt rendering
  / agent's reading conflated WATCHING-with-action with "held position."

Investigate the get_theses output for this run to know which.

**Failure mode B — `complete_run` accepted the run after the gate marked
it FAILED.** The promotion gate in `record_run_summary` correctly fired,
correctly transitioned ResearchRun.status to FAILED, and correctly wrote
a `run_failed` event. But the agent then narrated "I'll fix it next
session" and called `complete_run`. The atomic transition in
`complete_run` is RUNNING → COMPLETE, so once FAILED is set the run stays
FAILED — but the **agent doesn't know that and behaves as if the run
ended successfully**. The agent walked away from a recoverable
in-conversation rejection. This is the structural argument for moving
the promotion gate from post-run to a Layer-1 `complete_run` rejection
(the follow-on documented in PR #261).

This is a **diagnostic visibility bug, not a correctness bug** — the trades

## Raw Queries

```sql
-- Morning runs today + tool call totals
SELECT r.id, ac.name AS analyst, ac."useV2Prompt", r.status,
       EXTRACT(EPOCH FROM (COALESCE(r."completedAt", NOW()) - r."startedAt"))::int AS elapsed_s,
       (r.parameters->'toolStats'->>'totalToolCalls')::int AS total_tool_calls,
       r.parameters->>'error' AS error_text
FROM "ResearchRun" r
LEFT JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.mode = 'MORNING_PLAN'
  AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
ORDER BY r."startedAt";

-- Per-tool totals across today's morning runs
WITH today_runs AS (
  SELECT r.id FROM "ResearchRun" r
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
),
toolcall_rows AS (
  SELECT (regexp_matches(rm.content, '"type":"tool-call","toolCallId":"[^"]+","toolName":"([^"]+)"', 'g'))[1] AS tool_name
  FROM today_runs tr JOIN "RunMessage" rm ON rm."runId" = tr.id
)
SELECT tool_name, COUNT(*) AS n FROM toolcall_rows GROUP BY tool_name ORDER BY n DESC;

-- Trades + closes today
SELECT symbol, direction, status, quantity, "avgCost",
       ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS opened_et,
       ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS closed_et,
       "closeReason", "closeSource", "realizedPnl"
FROM "Position"
WHERE ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13'
   OR ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-13';

-- Overdue-review backlog
SELECT
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < (NOW() - INTERVAL '7 days')) AS overdue_7d,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < NOW()) AS overdue_any
FROM "Thesis";
```
