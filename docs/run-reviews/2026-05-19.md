## New Findings

### F1. Phantom F-trade — thesis ACTIVE, position CANCELLED

EV Catalyst Event Trader placed F SHORT at $13.03 during its morning run
(08:05:49 ET) via the `place_trade` tool. The thesis was promoted
WATCHING → ACTIVE and an STATUS_CHANGED audit row was written. Then 4
minutes later, the Position row flipped to `status=CANCELLED`,
`closeReason=MANUAL`, `realizedPnl=0`. No `update_thesis` audit row was
written to flip the thesis back; **the F thesis is still ACTIVE/SHORT in
the DB with no matching position**.

Possible causes:
- Alpaca rejected the SHORT order (short-locate failure, no borrow, F
  not on shortable list) — Alpaca reports back CANCELLED.
- The order timed out (no fill in N min) — Alpaca cancels.
- Manual cancel by user from the Alpaca console.

Whichever it is, the **architecture has no path to reconcile the thesis
state** when a Position flips to CANCELLED post-promotion. The agent
won't know on its next run that F isn't actually shorted — it'll read
the thesis as ACTIVE and the portfolio as not containing F, same
desync shape that P0-10 documented.

**Fix path:**
- (Layer 1, tool) When the Alpaca callback / poller flips a Position to
  CANCELLED, look up the matching Thesis. If `status=ACTIVE` and the
  Position is the only open one for that ticker, downgrade the thesis
  back to WATCHING with a STATUS_CHANGED audit row that says "trade
  cancelled by Alpaca/user — thesis restored to WATCHING."
- (Layer 2, agent) On run start, `get_portfolio_context` should
  include CANCELLED-but-no-fill positions and `get_theses` should
  flag the desync if any ACTIVE thesis has no matching OPEN position.

This is a slightly different polarity of P0-10 (which is
*reasoningSummary disagrees with status*); this one is *thesis status
disagrees with position status*. Both feed the same agent confusion
loop.

### F2. Ghost RUNNING — worse shape than P1-12's silent timeout

Yesterday's Secular Theme silent timeout (cmpb5xtcw) at least got marked
FAILED after the wall-clock cap. Today's Intraday Momentum Scalper run
(cmpcl97r1) is still showing `status=RUNNING` 12+ hours later, with
`completedAt=null`. The cron retry path correctly created a new run 5
min later that completed cleanly — that's the *good* news. The bad news:

- Any monitoring query that filters `status IN ('FAILED','COMPLETE')`
  will count this as "still running" rather than "failed silently."
- Any debugging tool that lists "today's failed runs" won't surface it.
- The retry path mitigates the user-facing impact (coverage doesn't get
  lost), but observability is broken.

Same root cause hypothesis applies as P1-12: model-side hang that
exceeds the function timeout, but doesn't trip the catch-path that
writes `parameters.error` and flips `status`. Now confirmed across 3
analysts (Earnings Drift 5/11+5/12, Secular Theme 5/18, Intraday 5/19).

**Fix path:** wall-clock-triggered finalizer. The cron's outer wrapper
should have a finally-block that checks "did the inner agent produce a
completedAt within the timeout window? If not, write
`status=FAILED, parameters.error='wall-clock timeout'`." Currently
that finally-block apparently doesn't run when the model hangs
silently.

  WHERE r.mode = 'INTRADAY_TACTICAL'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-19'
)
SELECT tt.analyst, tt.ticker, tt.pred_kind, tt.action,
       COUNT(tu.id) AS thesis_updates,
       BOOL_OR(tu."fieldChanges"::jsonb ? 'status') AS status_changed,
       MAX(tu."fieldChanges"::jsonb -> 'status' ->> 'to') AS to_status
FROM today_tactical tt
LEFT JOIN "ThesisUpdate" tu ON tu."runId" = tt.run_id
GROUP BY tt.analyst, tt.ticker, tt.pred_kind, tt.action, tt.run_id
ORDER BY tt.analyst, tt.ticker;

-- Focus ratio per analyst
WITH today_morning_runs AS (
  SELECT r.id AS run_id, r."agentConfigId", ac.name AS analyst, r.status
  FROM "ResearchRun" r
  JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
  WHERE r.mode = 'MORNING_PLAN'
    AND (r."startedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-19'
    AND r.status = 'COMPLETE'
),
touched_theses AS (
  SELECT DISTINCT tu."thesisId", tmr."agentConfigId"
  FROM "ThesisUpdate" tu
  JOIN today_morning_runs tmr ON tmr.run_id = tu."runId"
),
analyst_books AS (
  SELECT ac.id AS agent_config_id, ac.name AS analyst,
         COUNT(*) FILTER (WHERE t.status::text IN ('ACTIVE','WATCHING')) AS active_or_watching
  FROM "AgentConfig" ac
  LEFT JOIN "ResearchRun" rr ON rr."agentConfigId" = ac.id
  LEFT JOIN "Thesis" t ON t."researchRunId" = rr.id
  WHERE ac."enabled" = true
  GROUP BY ac.id, ac.name
)
SELECT ab.analyst, ab.active_or_watching,
       COALESCE(COUNT(DISTINCT tt."thesisId"), 0) AS touched_today,
       ROUND(100.0 * COALESCE(COUNT(DISTINCT tt."thesisId"), 0) / NULLIF(ab.active_or_watching, 0), 1) AS focus_ratio_pct
FROM analyst_books ab
LEFT JOIN touched_theses tt ON tt."agentConfigId" = ab.agent_config_id
GROUP BY ab.analyst, ab.active_or_watching
ORDER BY ab.analyst;

-- F-trade phantom-cancel investigation
SELECT symbol, direction, status, quantity, "avgCost", "closePrice",
       ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS opened_et,
       ("closedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York') AS closed_et,
       "closeReason", "closeSource", "realizedPnl"
FROM "Position"
WHERE symbol = 'F' AND ("openedAt" AT TIME ZONE 'UTC' AT TIME ZONE 'America/New_York')::date = DATE '2026-05-19';

-- Ghost RUNNING detection (run for 15+ min with no completedAt)
SELECT r.id, ac.name, r.status, r."startedAt",
       EXTRACT(EPOCH FROM (NOW() - r."startedAt"))::int AS elapsed_s
FROM "ResearchRun" r
JOIN "AgentConfig" ac ON ac.id = r."agentConfigId"
WHERE r.status = 'RUNNING'
  AND r."startedAt" < NOW() - INTERVAL '15 minutes'
ORDER BY r."startedAt";

-- Overdue-review backlog
SELECT
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')) AS active_or_watching,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < (NOW() - INTERVAL '7 days')) AS overdue_7d,
  COUNT(*) FILTER (WHERE status::text IN ('ACTIVE','WATCHING')
                   AND "nextReviewAt" < NOW()) AS overdue_any
FROM "Thesis";
